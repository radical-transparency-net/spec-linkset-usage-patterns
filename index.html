This specification defines ten interlocking Web-Linking and RFC 9264 Linkset usage patterns (RT-P01 through RT-P10) that formalize the foundational Declare layer of the Radical Transparency interoperability architecture. Building strictly on mature IETF, W3C, IANA, and OAI standards, these patterns enable digital resources, APIs, catalogs, and local files to declare profile conformity, available representations, persistent identity, and structural relationships in a machine-actionable way.

This is an unofficial community working draft maintained by the Radical Transparency Network at the Flanders Marine Institute (VLIZ). Feedback, cross-standard alignment notes (OGC, CODATA/CDIF, EOSC, FAIR Signposting), and pull requests are welcomed via the GitHub repository.

The companion RDF reification vocabulary referenced in The Semantic Bridge (rtwl:) is maintained in radical-transparency-net/semantic-assets.

The usage patterns in this specification (RT-P01 through RT-P10) are modular and independently adoptable according to architectural role (for example, RT-P05 applies to subsetting APIs, RT-P07 to federated catalogs, and RT-P10 to detached local storage). An implementation claims conformance on a per-pattern basis by satisfying all applicable normative requirements of each pattern it adopts, as declared via RT-P01.

Normative requirements in this specification apply across two distinct conformance classes:

  • Providers (Publishers): HTTP servers, APIs, catalogs, and local-storage packagers emitting HTTP Link headers, RFC 9264 linksets, api-catalog documents, or ResourceSync-augmented sitemaps. Providers follow conservative serialization rules to enable deterministic machine validation.
  • Consumers (Machine Agents): Crawlers, harvesters, validators, and client applications resolving rel="profile" declarations, recursive schema:hasPart chains, and linksets. Consumers support documented interoperability variants as specified by each adopted pattern.
